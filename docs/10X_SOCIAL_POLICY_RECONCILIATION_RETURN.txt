6. PERMISSIONS / EXTERNAL FEATURES - SOURCE FINDINGS AND LIMITS

Email login submits the supplied email through the configured API and consumes
an upstream session token. QR/mobile login exchanges synchronization messages
and decrypts an upstream auth token. The reviewed code does not establish the
exact server-side permission scopes, lifetime or upstream revocation UI.

Logout clears local auth, onboarding/key transport and caches. The reviewed
AuthProvider signOut does not call upstream token revocation. The shared SDK has
DELETE /v2/auth and PATCH /v2/auth/sessions/revoke methods, but their presence is
not proof that the client invokes them or that a published user procedure has
been tested. No active-session management page was found in this web client.
Do not describe local logout as upstream revocation or publish an unverified
revocation menu path. Confirm both login flows using a designated test account.

The source remains external-wallet-only. Embedded bridge and other signing
paths still exist and need end-to-end review on each supported network. The
configured migration/export origin remains the official upstream origin; this
review did not open a wallet or request a signature or transaction.

Mini App SDK context can expose FID, username, display name, profile picture,
profile location, launch context, client identity and added status. Notification
details are conditional on upstream enabled preferences. This is source evidence,
not a recording of every Mini App's actual calls or a determination of its legal
role. Review the disclosure before launch and each actual permission request.

KLIPY is off in the reviewed local release artifact. Its direct API integration
can be enabled by other builds; live enablement was not established here.
Messaging, media, notifications, stored keys, upstream access and substantiated
encryption properties remain to be verified in authenticated test flows. No

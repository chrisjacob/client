1. IMPLEMENTED IN THE SOCIAL CLIENT

The white-label Privacy and Terms pages remain short explanations, with normal
links to the full documents plus:
  https://app.10x.meme/privacy#10x-social
  https://app.10x.meme/terms#10x-social

They also link to the relevant upstream Farcaster application policies. The
Terms summary explicitly states the 18+ requirement. Legal/operator contact
placeholders remain configurable. The routes are still registered among the
public routes; no login requirement, iframe, runtime policy scraping, policy
copy, new agreement checkbox, or acceptance record has been introduced.

Delete Account no longer directs users to the inherited Neynar email address
or repeats an unverified account-verification procedure. It directs upstream
requests to the current Farcaster privacy notice and Code Hunt requests to
the Social section of the shared policy. Earlier cleanup already removed the
zero-account-storage claim and one-week deletion promise. Support now provides
the shared reporting/request links without promising a monitored inbox or a
particular outcome/timeframe.

Inherited PostHog is disabled whenever VITE_10X_FEATURE_WHITELABEL=true. This is
enforced in the SDK wrapper's startup state and enable() method. White-label
calls do not initialize the inherited project, capture pre-login or signed-in
events, identify users, set account properties, read analytics device/session
IDs, or request PostHog feature flags. A caller cannot re-enable it through
Analytics.enable(). White-label mode off preserves the upstream lifecycle.

This control does not delete previously transmitted data or existing browser
records. The operational device identifier, session storage and authentication
requests remain necessary parts of the account flow and have not been removed.
It does not block hosting/CDN analytics, third-party Mini Apps, upstream API
logs, or analytics inside separately operated wallet/services.

Functional consequence: PostHog-provided promotions and remotely gated Snap
transaction execution remain off when that SDK is not initialized. Local 10X
feature flags are separate. We have not silently enabled financial execution
paths to compensate for missing upstream flags.

The local tunnel's VITE_FARCASTER_API_BASE_URL override was moved from
.env.local to the ignored .env.development.local. Vite reads .env.local during
production builds too, so leaving the tunnel URL there could accidentally make
a future published build depend on the developer's running machine.

  Email login sends the supplied address through the configured API. Mobile/QR
  login exchanges synchronization messages and obtains a session token.
  Authentication and onboarding state use localforage; a stable browser device
  ID uses localStorage and is sent upstream. Sign-out clears local auth state,
  key transport and caches. The reviewed signOut function does not demonstrate
  upstream token revocation. Verify the actual account/device revocation route
  and scopes for both login flows before giving procedural instructions.

Wallets:
  external-only is present in both source and the inspected public entry.
  Upstream bridge and silent authentication-signing code still exists. This
  review does not prove those paths are unreachable in all contexts or establish
  every network-specific flow. Verify wallet-export/migration destinations and
  current provider behavior before publishing instructions. No wallet or account
  transaction was performed during this work.

Messages / Mini Apps / media:
  The client contains private messaging and third-party Mini App integration.
  Their full routing, context disclosures, storage/access and encryption were
  not established by this review. No end-to-end encryption promise was added.
  KLIPY calls its own API directly when enabled; source defaults are not proof
  of deployed flags, provisioned credentials or provider settings. Confirm which
  features are enabled and the context each actual provider receives.

Records / hosting / transfers:
  No dedicated Code Hunt account database is implemented in the reviewed relay.
  This does not establish the absence of other systems, logs or server-side

  contextual notices, consent mechanisms or acceptance records have NOT been
